Resumen

TransmiFlow es un prototipo académico orientado al monitoreo y control de aglomeraciones en estaciones del sistema TransMilenio de Bogotá. La propuesta integra una aplicación móvil, sensores simulados, una base de datos en la nube y una plataforma web administrativa para facilitar la supervisión operativa, el reporte ciudadano y la generación de alertas en tiempo real. El documento presenta la definición del problema, los objetivos, el alcance, las limitaciones, los actores, los requerimientos funcionales y no funcionales, los casos de uso, las historias de usuario y los resultados esperados del sistema. La organización del contenido permite comprender la solución desde una perspectiva técnica, funcional y académica.

Palabras clave: aglomeraciones, aplicación móvil, monitoreo inteligente, sensores, TransMilenio.

Introducción

El sistema TransMilenio constituye uno de los principales medios de transporte público de Bogotá y, debido a su alta demanda, puede presentar situaciones de congestión, desorganización y percepción de inseguridad en determinadas estaciones y horarios. En este contexto, resulta pertinente plantear soluciones tecnológicas que permitan mejorar la identificación temprana de aglomeraciones y apoyar la toma de decisiones por parte de una central operativa.

TransmiFlow se plantea como un prototipo académico que combina reportes ciudadanos, sensores simulados y una plataforma centralizada para monitorear el estado de estaciones seleccionadas. El propósito del sistema no es conectarse a la infraestructura real de TransMilenio, sino demostrar cómo una solución inteligente podría contribuir a la gestión del flujo de pasajeros, la generación de alertas y el análisis histórico de ocupación.

Objetivos

Objetivo general

Diseñar e implementar un prototipo funcional de sistema inteligente para el monitoreo y control de aglomeraciones en el sistema TransMilenio de Bogotá, mediante el uso de sensores simulados, aplicación móvil y plataforma central, con el fin de mejorar la seguridad, optimizar el flujo de pasajeros y facilitar la toma de decisiones en tiempo real por parte de la central operativa.

Objetivos específicos

  • Identificar los problemas actuales relacionados con la congestión y la falta de información en estaciones de TransMilenio.
  • Diseñar un sistema que permita monitorear la cantidad estimada de pasajeros en tiempo real.
  • Desarrollar una aplicación móvil que permita a los usuarios reportar aglomeraciones.
  • Implementar una plataforma central para la supervisión de estaciones y la gestión de alertas.
  • Crear un sistema de alertas automáticas que apoye la respuesta de la central operativa.

Alcance y limitaciones

El alcance del proyecto se delimita como un prototipo académico demostrativo. La primera versión se enfoca en cinco estaciones seleccionadas y utiliza sensores simulados para representar el comportamiento de ocupación. La solución considera una aplicación móvil, una plataforma web administrativa, una base de datos en la nube y un sistema de notificaciones.

Análisis del problema

La congestión en estaciones de transporte masivo puede generar tiempos de espera elevados, acumulación de pasajeros, estrés en los usuarios y dificultades para la gestión operativa. En el escenario planteado, se identifica que la falta de información en tiempo real limita la capacidad de respuesta ante situaciones de alta ocupación.

Actualmente, la propuesta parte de la necesidad de integrar dos fuentes de información: datos de ocupación obtenidos por sensores simulados y reportes manuales enviados por usuarios desde una aplicación móvil. La combinación de estas fuentes permitiría detectar aglomeraciones con mayor oportunidad y entregar información útil a la central operativa.

Problemas identificados

  • Sobrecupo en estaciones durante periodos de alta demanda.
  • Falta de información en tiempo real para usuarios y operadores.
  • Riesgos asociados a seguridad, movilidad y organización interna.
  • Aumento de estrés e inconformidad en los usuarios.
  • Dificultad para generar reportes históricos de ocupación.

Propuesta de solución

La solución propuesta consiste en desarrollar TransmiFlow, un sistema compuesto por una aplicación móvil, sensores simulados, una base de datos en la nube, una plataforma web administrativa y un panel de control para la central. El sistema permitirá detectar aglomeraciones, enviar alertas, mostrar el estado de estaciones y generar reportes históricos.

Resultados esperados

Con la implementación del prototipo TransmiFlow se espera mejorar la visibilidad sobre el estado de ocupación de las estaciones seleccionadas, centralizar reportes ciudadanos y facilitar la emisión de alertas ante condiciones de alta congestión. Además, el sistema permitirá consultar información histórica para apoyar análisis posteriores sobre comportamiento de ocupación y frecuencia de alertas.

Desde el punto de vista académico, el proyecto permitirá demostrar la integración de una aplicación móvil, sensores simulados, una base de datos en la nube y un panel de supervisión. Esta integración servirá como base para validar el flujo de información desde la captura de datos hasta la generación de reportes y notificaciones.

Aspectos que se espera mejorar

  • Identificación temprana de estaciones con alta ocupación.
  • Disponibilidad de información organizada para la central operativa.
  • Comunicación oportuna de alertas a usuarios y responsables del sistema.
  • Reducción de desorden operativo mediante seguimiento centralizado.
  • Generación de históricos que faciliten análisis y toma de decisiones.
  • Demostración de una arquitectura escalable para futuras versiones del prototipo.

Conclusiones

TransmiFlow se plantea como una solución académica pertinente para explorar el uso de tecnologías de monitoreo, reportes ciudadanos y plataformas centralizadas en contextos de transporte masivo. Aunque el prototipo no se conecta a sistemas reales ni utiliza hardware físico, su estructura permite representar un flujo completo de detección, procesamiento, alerta y consulta histórica.

La reorganización de requerimientos, actores, casos de uso e historias de usuario facilita el desarrollo posterior del sistema, ya que permite identificar con mayor claridad qué debe hacer la plataforma, quiénes interactúan con ella y cuáles son los criterios mínimos de calidad esperados. En conjunto, el documento sirve como base formal para continuar con etapas de diseño, prototipado, implementación y validación.
